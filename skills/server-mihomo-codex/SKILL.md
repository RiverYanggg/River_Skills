# Linux 服务器 Mihomo 与 Codex 配置

在用户指定的 Linux 普通账号中完成：安装内核 → 导入订阅 → 选择可用节点 → 后台运行 → 终端代理 → 登录自动检测 → Codex 安装与订阅登录验证。Agent 可在服务器本机执行，也可在本地通过用户已有 SSH 连接执行。区分本地和远端命令，不把本地 localhost 代理当成远端代理。

## 输入和探测

复用会话已有 SSH 目标、订阅和用户选择。真正缺少时询问 SSH 连接方式、Clash/Mihomo 格式订阅或配置、期望出口地区及登录方式。默认配置当前普通用户；端口探测后选择并保留已有可用端口，不能固定复制某台机器的端口。期望美国出口仅在用户需要时设置，不视作 Codex 的普遍要求。

自行探测发行版、架构、Shell、HOME、已有软件/配置、端口和 systemd 用户管理器。SSH 用户名含 `@` 时优先 `ssh -l 'account@partition' host`；主机及账号均来自用户，不虚构。先完成可独立推进的安装，再处理用户自己的网页登录。

## 工作流

1. 阅读 [部署流程](references/setup.md)，沿用已有配置，备份将修改的文件。无 sudo 的 Rocky/RHEL 可使用个人目录原生二进制；不强行运行 apt、不为原生 Codex 增装 Node。
2. 服务器无法下载时，在可联网的本机获取官方包、校验摘要，经 SSH 上传并再次校验。订阅链接和节点配置属于凭据，不回显、提交、写入测试夹具或放到公开命令示例；订阅下载仅使用用户提供或确认的地址。
3. 保留订阅 DNS、节点、代理组和规则。只按证据修改；先用 `mihomo -t` 验证，再启动用户服务。监听回环、禁用 TUN；控制接口优先带权限限制的 Unix socket，TCP 控制接口则回环监听并使用随机 secret。
4. 选择用户偏好的可用节点。分别核对普通代理组与 OpenAI 专用组，持久化选择；只改普通组可能让登录仍走坏节点。服务 active 或延迟测试通过不是最终联网证据。
5. 按用户要求配置终端代理与 `scripts/proxycheck.sh`。仅交互式 Bash 自动检测；保留 `proxycheck` 手动命令。后台服务不自动继承 `.bashrc`，`systemctl --user enable` 不等于机器重启后无人登录也能运行；不为测试擅自启用 linger。
6. 安装 Codex 原生 CLI，检查版本、帮助和 PATH。订阅登录用当前 CLI 支持的 `codex login --device-auth`；用户自行浏览器授权，遵守其“自己登录”的选择。密钥登录仅在用户选择时使用，不复制本机认证文件。
7. 阅读 [诊断与验收](references/verification.md)，分别验证出口、OpenAI TLS/HTTP、交互式登录提示、Codex 登录状态。未实际完成账号授权或真实模型请求时明确写“尚未验证”。

## 交付与边界

提供配置位置、服务和代理端口、当前节点、启停/查日志/手动检测命令、登录命令及真实测试结果。报告是个人用户服务还是系统服务、跨退出/重启的实际保证。不在共享超算登录节点运行计算作业；遵守平台对联网和常驻服务的规定。

不以“DNS 失败”“403”“代理延迟接口失败”单独认定订阅失效或平台封锁。按层排查，保留失败证据与假设的区别。授权配置不等于授权发布真实订阅、安装全局系统服务或替用户完成账户验证。
